# 本地 Dify + Ollama 模型选型

## 1. 已检测硬件

- CPU：AMD Ryzen 9 8945HX；
- 逻辑处理器：32；
- GPU：NVIDIA GeForce RTX 5070 Ti Laptop GPU；
- 独立显存：12227 MiB，约 12 GB；
- 检测时空闲显存：11192 MiB；
- Ollama 已安装。

检测时 Unity/PDC 未处于完整展示负载，实际运行 VR 后的空闲显存会明显减少。

## 2. 当前已有模型

| 模型 | 磁盘大小 | 用途判断 |
|---|---:|---|
| `qwen3.5:9b` | 6.6 GB | AI 对话与结构化指令首选测试模型 |
| `qwen2.5:7b` | 4.7 GB | 迎新现场稳定保底模型 |
| `qwen2.5:14b` | 9.0 GB | 与 Unity/PDC 同机运行风险较高 |
| `qwen2.5:3b` | 1.9 GB | 低延迟链路测试与应急模型 |

| `qwen2.5-coder:14b` | 9.0 GB | 编程模型，不适合校园向导主模型 |
| `deepseek-coder-v2:16b` | 8.9 GB | 编程模型，不适合现场主模型 |
| `gpt-oss:20b` | 13 GB | 无法完整放入 12 GB 显存，不推荐同机展示 |

## 3. 最终选型

### 开发和功能测试

使用 `qwen3.5:9b`：

- 中文对话和多轮上下文能力更强；
- 适合测试空间指代、角色回答和结构化动作；
- 当前电脑可运行；
- 必须同时观察 PDC 帧率和显存占用。

### 正式迎新展示

默认准备 `qwen2.5:7b` 作为稳定模式：

- 模型只占约 4.7 GB；
- 为 Unity、PDC、Avatar 和场景纹理保留更多显存；
- 降低串流掉帧和模型转移到系统内存的风险；
- 对校园知识库问答和简单 JSON 指令已经够用。

如果实机压力测试中 `qwen3.5:9b` 仍能保持头显稳定帧率，则正式展示可升级到 `qwen3.5:9b`。

### 应急模式

使用 `qwen2.5:3b` 或 Unity 本地预设回复：

- 用于网络、Dify 或 GPU 资源异常时保底；
- 确保注视、UI、导航和场景控制仍可演示。

## 4. Dify 参数基线

- 最大上下文：先限制在 8192 Token；
- 单次最大回答：256～512 Token；
- Temperature：`0.2～0.4`；
- 回答长度：默认 2～4 句；
- VR 动作必须返回固定 JSON Schema；
- Unity 只执行白名单动作；
- 优先关闭长思考输出，降低首字等待时间；
- 校园资料通过 Dify 知识库检索，不依赖模型记忆猜测。

## 5. 压力测试通过标准

同时运行 Unity、PDC、Dify、Ollama 和 Avatar 后检查：

1. 头显帧率没有明显持续下降；
2. 转头时没有明显卡顿；
3. 模型首句回答等待时间可接受；
4. 显存没有长期接近耗尽；
5. 连续进行十轮问答不会越来越慢；
6. 场景切换后模型和语音链路仍可继续工作。

若 `qwen3.5:9b` 导致掉帧，直接切换 `qwen2.5:7b`，不要通过降低 VR 分辨率牺牲主要展示体验。
