# AI 增强虚拟校园——当前项目功能总结

## 1. PICO 4 串流与 XR

- 已接入 PICO PDC Live Preview 串流流程。
- XR 相机支持头显位置和旋转跟踪。
- 已处理首次或第二次 Play 才显示画面的相关初始化问题。
- 已配置 PICO 4 头显扬声器和麦克风，供后续 Avatar 语音对话使用。
- 已增加左右手柄显示和射线交互。
- 已处理手柄材质紫色以及 Shader 属性报错问题。

## 2. 场景结构

主项目目前包含三个场景：

1. 主校园
2. 教室
3. 展厅

场景切换操作：

- `X`：切换到上一个场景；
- `Y`：切换到下一个场景。

已处理展厅过黑、场景切换回来崩溃、XR 对象重复创建，以及切换后的相机和交互恢复问题。

## 3. 玩家移动

当前移动配置：

- 左摇杆：低速平滑移动，速度为 `1.4 m/s`；
- 右摇杆：每次 `45°` 分段转向；
- 右手 A：按住显示瞬移弧线，松开执行瞬移；
- 绿色弧线：存在有效落点；
- 红色弧线：当前不可瞬移；
- 默认不启用重力掉落，避免启动后坠落。

三个场景启动时都会自动生成一个 `5000 × 5000 米`的静态隐形地面碰撞箱，用于承接玩家和瞬移检测。该碰撞箱没有 Renderer，不会显示或遮挡画面。

## 4. 录取通知书引导精灵

当前使用两个扁方块作为通知书临时模型，后期可以替换为正式图片或模型。

已实现：

- 通知书漂浮在用户视野左下方；
- 不占据视野中心，尽量避免遮挡建筑；
- 自动跟随用户，并带有轻微漂浮动画；
- 左手射线命中通知书后，按左 Trigger 切换吸附；
- 吸附后通知书跟随左手，形成拿在手里的效果；
- 再按一次左 Trigger 松开通知书；
- 吸附到左手后关闭通知书碰撞箱，避免挡住右手 UI 射线；
- 松开后重新启用碰撞箱；
- 通知书位置异常、掉落或距离过远时自动恢复到用户身边。

## 5. 通知书主菜单

翻开通知书后会投影竖直悬浮 UI。

当前临时页面：

- AI 校园向导；
- 校园地图；
- 探索图鉴；
- 任务中心；
- 建筑详情页。

校园地图可以进入主校园、教室和展厅。教学中心是主校园中的一栋建筑，不是场景名称。

UI 操作：

- 使用右手射线指向按钮；
- 按右 Trigger 确认；
- 支持页面切换和返回主菜单；
- 当前使用临时文字及图片占位；
- 后期主要替换图片、文字和正式数据即可。

原主菜单的位置保持不变。

## 6. 建筑注视交互

头显视野中心会自动检测带有 `BuildingInfo` 的建筑：

- `0.3 秒`：建筑出现高亮；
- `0.8 秒`：确认建筑上下文，并打开通知书建筑详情页；
- `1.5 秒`：地点标记为已发现；
- `2.5 秒`：完成地点并获得印章；
- 视线离开：重置注视计时并自动关闭建筑详情 UI。

建筑详情页从通知书上方投影，比原主菜单高 `0.32 米`，显示建筑名称和测试介绍，不会修改原主菜单的位置。

## 7. 注视调试功能

测试阶段保留头显中心调试射线：

- 长度为 `5000 米`；
- 绿色：成功找到 `BuildingInfo`；
- 红色：命中了 Collider，但没有找到建筑信息；
- 青色：没有命中 Collider；
- 视野下方会显示命中对象名称或建筑名称。

正式打包前，在头显相机的 `GazeDetector` 中关闭：

- `Show Debug Ray`；
- `Show Debug Label`。

## 8. 地点数据与进度逻辑

已建立统一地点数据结构，包括：

- 唯一地点 ID；
- 地点名称；
- 地点介绍；
- 地点分类；
- 是否发现；
- 是否完成；
- 是否发放印章；
- 导航目标。

主校园已标注五栋建筑，并在未来科创中心一楼增加科创文化连廊展板参观点：

| locationId | 测试名称 |
|---|---|
| `main_innovation_center` | 国际创新中心 |
| `main_teaching_center` | 教学中心 |
| `main_innovation_corridor` | 科创文化连廊 |
| `main_future_tech_center` | 未来科创中心 |
| `main_east_wu_gate` | 东吴门 |
| `main_academic_exchange_center` | 学术交流中心 |

教室和展厅会生成蓝色测试热点，用于验证注视、建筑介绍、图鉴状态、印章、导航目标和存档恢复。

当前文字均为测试数据。后期替换正式内容时建议保留 `locationId`，否则旧存档会将其识别为新地点。

## 9. AI 接口预留

AI 与 UI 前端目前保持独立，尚未连接真实 Dify API。

当前已预留：

- 当前场景上下文；
- 最近注视地点；
- 建筑名称和介绍；
- 对话 ID；
- 用户问题；
- AI 回答；
- 聆听、思考和回答状态；
- Dify 指令载荷；
- Mock 测试回复。

真实 Dify HTTP 客户端已经完成。配置 API Key 后会自动替换 Mock 服务，并支持校园／闲聊／无关问题分类、知识库确定性约束、非结构化输出拦截和多轮会话。详细配置见 `09_Dify校园AI接入与约束.md`。

## 10. 新增高级反馈

- 地点首次被发现时，通知书产生蓝色灯光和材质脉冲；
- 首次获得探索印章时，通知书产生金色灯光、材质脉冲和粒子爆发；
- 获得印章时左右手柄同时震动；
- 所有效果均由程序生成，后期可以替换正式粒子、音效和通知书素材。

## 11. Mock AI 与安全动作

- 已统一 Mock、Dify 和本地 Ollama的输出协议；
- 已增加 Unity AI 动作白名单执行器；
- 已支持导航、打开页面、场景切换、舒适模式、展项启动和展示复位动作；
- 所有地点、页面和场景参数都会在 Unity 中二次校验；
- Mock 已能模拟闲聊、无关问题、不确定回答、地图、舒适模式和导航。

## 12. 兴趣方向与未来课表

- 通知书主菜单已增加“生成我的未来课表”入口；
- 支持数据科学与大数据技术、人工智能、机器人工程、机电工程四个校区专业；
- 每个方向生成不同测试课表；
- 支持重新选择，适合迎新现场重复体验；
- 兴趣已写入统一用户画像和 AI 请求上下文；
- 展示模式复位后会清除上一位体验者的兴趣。

## 13. 地图选点与金色星轨

- 校园地图已升级为目的地选择；
- 支持根据兴趣方向推荐地点；
- 支持当前场景和跨场景导航；
- 路线使用金色渐变和 18 个流动光点；
- 到达目标后自动结束并提供双手震动反馈；
- AI 导航目标必须通过地点注册表校验。

## 14. 推荐主线与按钮反馈

- 已加入约 12～14 分钟的十步推荐旅程；
- 推荐主线可以随时暂停或重新开启；
- 不锁定移动、场景、页面、专业和探索顺序；
- 自由探索完成的内容会自动计入推荐进度；
- 已修复按钮切页后保持高亮的问题；
- 按钮点击增加 0.12 秒金色缩放反馈并自动复位。

## 16. 展厅展品手持观摩

- 展厅内的四轴机械手、六足机器人、机械臂、机械狗和减速器精度测量装置支持手持观摩；
- 使用任一手柄射线指向展品并按住 Trigger 即可拿到手中；
- 移动和转动手柄可从各个方向观察，松开 Trigger 后展品自动平滑回到原位；
- 手中持有展品时，对应手柄射线自动隐藏，归位后恢复；
- 左手拿着合上的录取通知书时仍可继续注视建筑，只有翻开通知书阅读时才暂停建筑注视检测。
